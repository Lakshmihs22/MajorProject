================================================================================
2. FIRST-TIME BUILD (5–15 minutes)
================================================================================

In project root:

  docker compose build

If "docker compose" fails, try:

  docker-compose build

Expected: all services build without errors (redis, edge-node-1/2/3, sensors,
analysis-agent, lab-traffic-source, defender-agent, honeypot, dashboard).


================================================================================
3. STANDARD DEMO RUN (recommended default)
================================================================================

Real attack traffic + real sensors + simulated defender (safe for reports).

  docker compose up

Or run detached (background):

  docker compose up -d

Then follow logs:

  docker compose logs -f lab-traffic-source analysis-agent defender-agent sensor-agent-1

Wait ~60–90 seconds after start:
  - health-probe sends benign checks to edge-node-1
  - lab-traffic-source waits ~45s then starts multi-device campaign

URLs (on the laptop browser):
  Dashboard UI:  http://localhost:3000
  Dashboard API: http://localhost:8000/health
  Metrics:       http://localhost:8000/metrics
  Devices:       http://localhost:8000/devices
  Packet obs:    http://localhost:8000/packet-observations

Stop everything:

  docker compose down

Clean slate (deletes shared DB volume — destructive):

  docker compose down -v

6. LIVE CAMPAIGN (what lab-traffic-source does)
================================================================================

Not a single hardcoded victim chain. One adversary campaigns across devices:

  1. Port scan — all three edge IPs
  2. Brute force — industrial gateway (node-1)
  3. Lateral movement — node-1 → node-2 (IoT hub)
  4. Credential stuffing — IoT hub
  5. HTTP flood — IoT hub (port 80)
  6. DNS tunnelling — DNS utility edge (node-3)
  7. ARP recon — subnet
  8. DDoS impact — all nodes

Ground truth log (for evaluation metrics):
  /data/ground_truth.jsonl  (inside edgeshield-data volume)

Optional ML training after a run (inside a sensor container):

  docker compose exec sensor-agent-1 python src/train_model.py

Model path: /data/model.joblib (shared volume, all sensors can load it)

================================================================================
9. TROUBLESHOOTING
================================================================================

Docker: "cannot connect to Docker API"
  → Start Docker Desktop; wait until healthy.

Build fails on network/apt
  → Retry: docker compose build --no-cache defender-agent

No alerts on dashboard
  → Wait 2+ minutes; check: docker logs sensor-agent-1
  → Ensure lab-traffic-source is running: docker logs lab-traffic-source

Empty chain graph
  → Confirm alerts are sensor_live, not only synthetic_scenario
  → docker logs analysis-agent

Dashboard WebSocket disconnected
  → Should auto-reconnect; restart dashboard-frontend if needed

database is locked (rare)
  → docker compose restart analysis-agent defender-agent dashboard-backend

Windows firewall blocks localhost:3000
  → Use http://127.0.0.1:3000
