EDGESHIELD — HOW TO RUN & DEMO (final)

================================================================================
0. BEFORE YOU START
================================================================================

You need:
  [ ] Docker Desktop running (Linux containers / WSL2 on Windows)
  [ ] Free ports: 3000 (UI), 8000 (API), 6379 (Redis optional on host)
  [ ] ~8 GB RAM free for Docker
  [ ] This full repo folder copied or cloned onto the demo machine

Check Docker:
  docker version
  docker compose version

Optional static file check (no Docker):
  Windows PowerShell, from repo root:
    powershell -File scripts\preflight_file_check.ps1

================================================================================
1. ONE-TIME SETUP (REPO ROOT)
================================================================================

Windows:
  cd "C:\path\to\MajorProject-main"
  copy .env.example .env

Linux / macOS:
  cd /path/to/MajorProject-main
  cp .env.example .env

Fresh database (only if old data is broken):
  docker compose down -v
  WARNING: -v wipes the shared SQLite volume.

================================================================================
2. BUILD (FIRST TIME OR AFTER PULLING CODE)
================================================================================

From repo root, build everything:

  docker compose build

If Person C / defender / lab-traffic changed, rebuild at minimum:

  docker compose build lab-traffic-source defender-agent
  docker compose build

First build can take 10–20 minutes (sensors + Suricata + frontend npm).

================================================================================
3. START THE FULL STACK (STANDARD FINAL DEMO)
================================================================================

Start all 13 services:

  docker compose up

Or detached:

  docker compose up -d
  docker compose logs -f

Wait about 2–3 minutes after startup:
  - Redis healthy
  - health-probe begins benign curls (~25 s)
  - lab-traffic-source sleeps 45 s, then multi-device attack campaign
  - Sensors → Analysis → Defender → Dashboard pipeline

Open in browser:
  Dashboard:     http://localhost:3000
  API health:    http://localhost:8000/health
  Device fleet:  http://localhost:8000/devices
  Node health:   http://localhost:8000/node-health

================================================================================
4. DEFENDER / FIREWALL MODE (PERSON C — WHAT DEFAULT DOES)
================================================================================

docker-compose.yml sets:
  DEFENDER_ENFORCEMENT=auto

Meaning:
  - Docker socket is mounted on defender-agent → LIVE iptables in
    lab-traffic-source namespace (real lab rules, not host PC firewall).
  - No socket → simulated (audit only).

See active mode in logs:
  docker logs defender-agent 2>&1 | findstr /i ENFORCEMENT
  (Linux/mac: use grep instead of findstr)

You should see something like:  ENFORCEMENT = live (requested=auto)

Prove rules in adversary container (after a high tier response):
  docker exec lab-traffic-source iptables -L OUTPUT -n
  docker exec lab-traffic-source iptables -t nat -L OUTPUT -n

Force simulation only (safe pitch, no iptables):
  In .env or compose:  DEFENDER_ENFORCEMENT=simulation
  Then:  docker compose up -d defender-agent

Force live explicitly:
  DEFENDER_ENFORCEMENT=live
  Or overlay:  docker compose -f docker-compose.yml -f docker-compose.final-demo.yml up -d

Optional ping test while block/isolate active:
  docker exec lab-traffic-source ping -c 2 172.28.0.11

================================================================================
10. TROUBLESHOOTING
================================================================================

Docker cannot connect
  → Start Docker Desktop; wait until healthy.

No alerts
  → Wait 2–3 min after lab-traffic-source starts.
  → docker logs sensor-agent-1
  → docker logs lab-traffic-source

No chains
  → Alerts must be sensor_live (not only synthetic).
  → docker logs analysis-agent

No defender responses
  → FP guard needs ≥2 alerts on chain, ≥5 s apart; wait for campaign.
  → docker logs defender-agent

enforcement_mode always simulated
  → Confirm socket mount on defender-agent in docker compose ps.
  → Rebuild defender-agent; set DEFENDER_ENFORCEMENT=live if needed.
  → Rebuild lab-traffic-source (iptables must exist in that image).

Node health CPU/memory empty
  → Wait 20–30 s; defender thread polls docker stats.
  → docker logs defender-agent | findstr telemetry

Dashboard empty
  → curl http://localhost:8000/alerts
  → docker compose restart dashboard-backend dashboard-frontend
